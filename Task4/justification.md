# justification.md

## 1. Цели конфигурации

Короткая демонстрация инфраструктуры по диаграмме:

- отдельные компоненты (портал, доменные сервисы, БД, шина, API Gateway);
- автоматическое создание инфраструктуры через Terraform;
- локальный запуск без облака.

---

## 2. Обоснование ресурсов

### Compute / Services

| Компонент        | Реализация       | Зачем                                 |
|------------------|------------------|---------------------------------------|
| Портал           | контейнер nginx  | Stub портала для схемы                |
| Доменные сервисы | контейнер nginx  | Имитация сервисов медицины/финтех     |
| ETL              | контейнер alpine | Выделенный компонент платформы данных |
| API Gateway      | контейнер nginx  | Stub шлюза API                        |

### Data / Storage

| Компонент        | Реализация                  | Зачем                                        |
|------------------|-----------------------------|----------------------------------------------|
| Аналитическая БД | postgres:15                 | Витрины данных и аналитика                   |
| Диск             | docker volume               | Устойчивое хранилище, аналог облачного диска |
| Общее хранилище  | S3-заменитель в виде volume | Простое persistence-хранилище                |

### Networking

| Компонент | Реализация     | Зачем                              |
|-----------|----------------|------------------------------------|
| Сеть      | docker_network | Аналог VPC, изоляция всех сервисов |

### Event Streaming

| Компонент    | Реализация | Зачем                                                        |
|--------------|------------|--------------------------------------------------------------|
| Kafka (stub) | nginx      | Имитация шины событий (структурно на диаграмме присутствует) |

---

## 3. Порты и размеры

### Порты

| Компонент        | Порт | Причина                   |
|------------------|------|---------------------------|
| Портал           | 8080 | стандартный внешний порт  |
| Доменные сервисы | 8081 | отделение сервисов        |
| API Gateway      | 8088 | отдельная точка входа     |
| DB               | 5432 | стандарт PostgreSQL       |
| Kafka stub       | 9092 | сохраняем семантику Kafka |

### Размеры (локальная среда)

| Ресурс              | Значение     | Причина                                        |
|---------------------|--------------|------------------------------------------------|
| Диск (volume)       | динамический | Docker сам управляет, хватает для учебного DWH |
| RAM/CPU контейнеров | по умолчанию | Локальная разработка, нет нагрузки             |

---

## 4. Почему Terraform

| Преимущество           | Суть                                             |
|------------------------|--------------------------------------------------|
| Декларативность        | Описываем **что должно быть**, а не как          |
| Воспроизводимость      | Любой разработчик запускает одинаковую среду     |
| Масштабируемость       | Один и тот же код работает локально и в облаке   |
| Управление изменениями | `plan` показывает diff, изменения контролируются |
| Документирование       | Конфигурация = актуальная архитектура            |

---

## 5. Как это соответствует архитектуре «Будущее 2.0»

| Архитектурный элемент   | Соответствие в конфигурации |
|-------------------------|-----------------------------|
| Портал самообслуживания | контейнер `portal`          |
| Доменные сервисы        | контейнер `domain_services` |
| Шина событий            | контейнер `kafka` (stub)    |
| Платформа данных        | БД + ETL                    |
| API Gateway             | контейнер `api_gateway`     |
| Хранилище               | docker volume               |
| Сеть VPC                | docker network              |
